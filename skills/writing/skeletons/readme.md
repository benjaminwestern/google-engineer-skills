# README skeleton

Voice: instructional, warm, direct. Address the reader as "you". Register: straight by default. A README's job is to get a reader from nothing to running, then oriented enough to go deeper.

Candidate shape, in reading order. Drop any section that would be thin, and fold it into a neighbour.

- **Title and one-line description** — what this is, in a single sentence, above the fold.
- **Overview** — what the project does and the problem it solves, in a short paragraph. State what it is not, if that heads off a common misconception.
- **Quick start** — the shortest path to a working state: install, minimal config, first successful command. Lead with the commands, add a sentence on what each does.
- **Usage** — the common tasks a user actually performs, with real examples. Explain the why, not just the invocation.
- **Configuration** — options that matter, ideally as a table with a lead-in and an interpretive close.
- **Development / contributing** — how to build, test, and contribute, if the project takes contributions.
- **License and links** — license, and links to deeper docs.

Keep the quick start honest: it should actually work when copied. Cite external tools or services inline only where a reader would want to verify a specific claim.
